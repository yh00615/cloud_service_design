QuickTable이란?

QuickTable은 전 세계 사용자가 레스토랑을 검색하고 예약할 수 있는 글로벌 서비스입니다. AWS 클라우드 서비스를 활용하여 고성능, 고가용성 아키텍처를 구현합니다.

글로벌 아키텍처

┌─────────────┐
│   사용자     │  (서울, 도쿄, 뉴욕, 런던 등)
└──────┬──────┘
       │
       ▼
┌─────────────────────┐
│   Amazon CloudFront  │  ← 엣지 로케이션 (전 세계)
│   Distribution       │    HTTPS, 캐싱, OAC
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│   Amazon S3 Bucket   │  ← 오리진 (ap-northeast-2)
│   (Private, OAC)     │    정적 웹사이트 파일
└─────────────────────┘

CloudFront로 글로벌 CDN 배포

캐싱 전략 가이드

파일 유형별로 적절한 TTL을 설정하면 성능과 콘텐츠 신선도를 균형 있게 유지할 수 있습니다.

HTML

index.html, about.html

권장 TTL: 짧게 (예: 300초)

자주 변경되는 콘텐츠

CSS

style.css

권장 TTL: 중간 (예: 3600초)

버전 관리로 갱신 가능

JavaScript

script.js

권장 TTL: 중간 (예: 3600초)

버전 관리로 갱신 가능

이미지

로고, 배너 등

권장 TTL: 길게 (예: 86400초)

거의 변경되지 않는 콘텐츠

CloudFront 모범 사례

  • 파일 타입별 TTL 설정: 정적 파일은 길게, 동적 콘텐츠는 짧게 설정합니다.
  • 압축 활성화: Gzip/Brotli 압축으로 전송 크기를 줄여 속도를 향상시킵니다.
  • HTTPS 사용: CloudFront 기본 인증서 또는 ACM 커스텀 인증서로 보안을 강화합니다.
  • OAC 사용: S3 버킷을 비공개로 유지하고 CloudFront를 통해서만 접근하도록 합니다.
  • 캐시 키 최적화: 불필요한 쿼리 스트링, 헤더, 쿠키를 캐시 키에서 제외합니다.

문제 해결

403 Forbidden 오류

원인: S3 버킷 정책이 CloudFront OAC를 허용하지 않음

해결: CloudFront가 제안하는 버킷 정책을 복사하여 S3 버킷에 적용

오래된 콘텐츠가 표시됨

원인: 캐시 TTL이 아직 만료되지 않음

해결: CloudFront 콘솔에서 캐시 무효화(Invalidation) 생성

느린 첫 로딩

원인: 캐시 미스 (Miss from cloudfront)

정상: 첫 요청은 오리진에서 가져오므로 느릴 수 있음. 이후 요청은 캐시에서 빠르게 제공됨
